# 앱 CRM 캠페인 제작 흐름 (Agent 04 → Agent 05)

서브에이전트는 다른 서브에이전트를 부를 수 없다. 그래서 이 흐름은 **메인 세션이 순서대로 지휘**한다. 각 단계의 결과를 다음 에이전트 프롬프트에 그대로 넘긴다.

## 0. 요청 분류
- **배너 제작/수정**: 아래 1~5단계를 진행한다.
- **푸시 단독**: Agent 04만 호출한다. 배너 스튜디오는 건드리지 않는다. 푸시에 이미지가 필요할 때만 Agent 05를 호출한다.
- **기존 배너 일부 수정**(예: "메인 카피만 바꿔 줘"): Agent 04가 `plan:show`로 기존 기획안을 확인하고 해당 필드만 고쳐 `plan:save`한다. Agent 05는 이미지·레이아웃을 그대로 두고 미리보기와 검수만 한다. 변경 전후를 비교해 보고한다.

확정되지 않은 할인율·기간·혜택은 사용자에게 묻거나 `확인 필요`로 둔다. 대상 배너가 둘 이상으로 해석되면 진행 전에 확인한다.

## 에이전트 이름
플러그인으로 설치된 경우 이름 앞에 플러그인명이 붙는다. 목록에 있는 이름을 그대로 쓴다.
- Agent 04: `app-crm-campaign:agent-04-app-crm-campaign` (저장소 `.claude/agents`로 쓰면 `agent-04-app-crm-campaign`)
- Agent 05: `app-creative-studio:agent-05-app-creative-studio` (저장소 `.claude/agents`로 쓰면 `agent-05-app-creative-studio`)
- Agent 05가 목록에 없으면 `app-creative-studio` 플러그인 설치가 필요하다고 사용자에게 알리고 기획 단계까지만 진행한다.

## 1. Agent 04 — 기획
프롬프트에 사용자 요청 원문과 확정 조건을 넣는다. 받아야 할 결과:
- 배너 가이드(`skdj-ad-review`) 확인 결과: 트랙, 버전, 적용 규격
- 캠페인 개요·전략, 카피 A/B/C와 추천안, KPI·A/B 가설
- 디자인 브리프
- `plan:save`로 저장한 기획안의 bannerId와 version, 이미지 후보(`asset:search` 결과)

## 2. Agent 05 — 제작·반영
프롬프트에 Agent 04 결과 전체(브리프, bannerId, 후보 Asset ID, 미확정 항목)를 넣는다. Agent 05가 할 일:
- 배너 가이드 확인
- 레퍼런스 3개 이상 조사
- 에셋 검색 → 재사용 → 수정 → 신규 생성(Higgsfield) 순서로 이미지 확보. 신규 생성은 크레딧이 드니 Agent 05가 근거와 예상 크레딧을 먼저 보고하게 한다.
- 타입 키와 옵션값 매칭 → 기획안에 Asset ID·배치 연결 → `plan:save`
- `tools/preview-banner.mjs`로 캡처하고 검수(반려 0건 목표)
- `validate`와 테스트 통과 확인

## 3. 승인 지점 (사용자 확인 필요)
- Higgsfield 신규 이미지 생성 (크레딧 사용)
- design 저장소 커밋·푸시와 Vercel 프로덕션 배포
- 실제 앱 푸시 발송

## 4. 최종 보고서 — [앱 CRM 캠페인 및 크리에이티브 제작 보고서]
1. 캠페인 개요: 캠페인명, 목적, 타깃, 운영 기간, 핵심 혜택, 주요 KPI
2. 캠페인 전략: 핵심 메시지, 사용자 니즈, 소구점, 추천 방향
3. 배너 카피: 메인, 서브, CTA, 대안 카피, 추천 근거
4. 디자인 레퍼런스: 이름, 출처 URL, 특징, 적용 요소
5. 크리에이티브 에셋: 이미지, 재사용/신규 여부, 저장 경로, Asset ID, 생성 도구·프롬프트
6. 배너 스튜디오 적용 결과: 배너명, 매칭된 옵션값, 적용 파일, 카피, 이미지, 기획안 버전, 미리보기
7. 앱 푸시 기획(요청 시): 제목, 본문, 타깃, 발송 시점, 딥링크
8. 전환 최적화: KPI, A/B 방향, 측정 방안
9. 최종 검수: 적용 가이드, 규격 준수, 옵션값 일치, 시각 오류, 완료 항목, 미완료·확인 필요 항목

- **기획안과 시안은 저장소에 저장하는 것으로 끝내지 않고 바로 세션에 보여준다.** 단계마다(기획 직후, 시안 직후) 메인 세션이 기획안 요약 md와 미리보기 PNG를 작업 폴더에 두고 SendUserFile(display: render)로 직접 보낸다. 서브에이전트가 보낸 파일은 사용자에게 안 보일 수 있다.
- 실제로 실행·확인하지 않은 단계는 "미실행" 또는 "미확인"으로 적는다.
